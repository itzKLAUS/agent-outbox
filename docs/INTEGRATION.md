# Integration contract

1. Store the business write and intent in one local SQLite database. Use an explicit transaction on the connection passed to `enqueue`; commit only if both succeed. Roll back on any exception. The library verifies the main database path and refuses autocommit enqueue. It does not enlist another database or remote service in that transaction.
2. Establish a tenant scope and immutable client key in the trusted application. One key identifies one operation, target, finite JSON payload, mode, deadline and attempt limit. Different specifications conflict. New intents must expire in the future. Payloads are limited to a canonical JSON representation of 64 KiB; the entire idempotency specification must also fit that bound.
3. Resolve operation and target through a trusted allowlist. An LLM must not choose arbitrary network destinations, Python functions or shell commands from stored strings. Validate the actual tool payload and authorization independently before invocation.
4. Default to `once`. Opt into `retry_safe` only when the exact downstream operation durably deduplicates `lease.idempotency_key` across its complete retry window. Transient in-memory caching or an idempotent-looking HTTP verb is insufficient. Retries may overlap a still-running old worker.
5. Pass the immutable intent ID as the downstream idempotency key on every attempt. Fence numbers change with each claim; using them as idempotency keys would create new external operations. Forward the fence separately only if the destination implements its own monotonic-fence contract.
6. Run tools outside database transactions. Choose a lease long enough for the operation or renew before expiry. Synchronous `Worker.step` does not automatically renew. If your adapter cannot complete inside the lease, use `claim`, `renew` and `succeed` directly, with a separate renewal coordinator.
7. `Worker.step` records ordinary exceptions as ambiguous. `RetryableError` is consumed after recording; other exceptions are re-raised for diagnostics. Process exit and cancellation leave the lease for recovery. Invalid results or stale acknowledgements also leave recovery/reconciliation work. Do not turn these errors into an untracked second tool invocation.
8. Return a finite JSON result of at most 64 KiB for hashing, or return a digest/receipt summary rather than a large or sensitive raw result. Raw results are not persisted. The digest uses this package's deterministic Python JSON encoding, not an RFC 8785 cross-language canonicalization claim.
9. Protect operator access to `resolve`. Check independent downstream receipts before declaring success or definitive failure, supply the current fence, and retain the evidence whose digest is recorded. There is no retry transition from uncertain; a newly authorized action requires a distinct business key after reconciliation.

Connections returned by `connect()` use explicit transaction control. Closing an uncommitted connection rolls back. The connection context manager does not commit automatically. Use `BEGIN IMMEDIATE` for business transactions that will enqueue to avoid read-to-write lock upgrade races.

This library does not wrap asynchronous adapters, schedule a service, provide authentication, calculate budgets, or enforce human approvals. It can be composed with an approval gateway such as Delegation Gate or Action Ledger, but that composition has not been verified here.
